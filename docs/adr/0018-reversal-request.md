# ADR-0018: 역분개 요청 — 작성자가 정정 전표를 올리고, 승인자가 전기한다

- 상태: 채택 (2026-11-24)

## 맥락
전기된 전표는 고치거나 지울 수 없고, 정정은 반대 분개(역분개)로 한다 (불변식 2, [ADR-0003](0003-immutable-posted-journal.md), [회계 노트 02](../accounting-notes/02-journal-posting-reversal.md)).
지금의 역분개(`JournalService.reverse`)는 반대 전표를 만들어 **바로 전기**하고, 승인자(APPROVER) 이상만 쓸 수 있다.

실습자는 작성자(WRITER)다 ([ADR-0014](0014-sandbox-company-per-learner.md) — 신입의 실제 권한). 그래서:

- 설계 1장의 "잘못 전기한 전표를 역분개로 고치기"를 실습자가 할 수 없다
- 설계 §7의 "1장 뒤로는 사용자가 직접 전기할 수 있는 미션을 섞는다"도 이 권한과 부딪힌다

정정도 장부를 바꾸는 일이라 결재를 거치는 것이 자연스럽다. 작성자가 정정 전표를 올리고 승인권자가 결재하는 흐름이 일반적이라고 보지만, 특정 회계 프로그램의 화면 흐름은 확인하지 않았다.

## 결정
ERP에 **역분개 요청**을 더한다. 실습 층 전용이 아니라 자유 모드에서도 쓰는 ERP 기능이다 ([ADR-0012](0012-learning-layer-on-top-of-erp.md)).

1. 작성자(WRITER)가 전기된 전표에 대해 역분개를 요청하면, 원전표와 차대가 반대인 REVERSAL 전표가 **임시(DRAFT)** 로 저장된다. 라인은 시스템이 원전표에서 만든다 (`JournalEntry.reversalOf` 재사용)
2. 요청 전표의 **라인은 고칠 수 없다.** 날짜·사유만 고치거나 요청을 지울 수 있다. 라인을 고칠 수 있으면 "역분개"라는 이름의 임의 전표가 원전표를 가리키게 된다 → `JournalEntry.replace`가 REVERSAL이면 라인 변경을 거부, 테스트로 고정
3. 승인자는 다른 임시 전표처럼 전기한다 (`post`). 전기할 때도 기간이 열려 있는지 다시 본다 (지금의 `post`와 같음)
4. 원전표당 역분개는 하나 — 지금의 유니크 인덱스 `ux_journal_entry_reversal_of`가 임시 요청에도 걸린다. 요청이 남아 있으면 같은 전표를 다시 요청할 수 없다 (의도)
5. 지금의 즉시 역분개(`reverse`, APPROVER)는 남긴다 = 요청 + 즉시 전기
6. DB 방어선: V3의 `check_reversal_target`(원전표가 같은 회사·POSTED·REVERSAL 아님)은 임시 요청에도 그대로 맞다. 임시 REVERSAL의 라인 변경도 DB 트리거로 막는다 ([ADR-0006](0006-balance-check-in-app-and-db.md)의 "앱과 DB 양쪽" 원칙). 라인은 요청을 만들 때 한 번만 들어가고, 그 뒤의 라인 추가·수정·삭제는 거부한다. 단, DRAFT 요청을 전표째 지울 때 라인이 함께 지워지는 것은 허용한다. 트리거로 이것을 가르는 구체적인 방법은 구현 때 정하고 DB 직접 공격 테스트(JournalDatabaseGuardTest)로 고정한다

실습 쪽:

- 정정 = "역분개 요청 + 올바른 전표" 두 장을 함께 결재 요청한다. 둘 다 임시 전표라서 지금의 채점(전기된 잔액 + 임시 전표의 변화)이 그대로 채점한다. 정정 미션은 원전표를 가리키는 REVERSAL이 있는지 추가로 본다 ([ADR-0017](0017-mission-kinds.md)의 correction)
- 실습자는 종합 실전 전까지 작성자다. "잘못 전기된 전표"는 실습자가 직접 전기해서 만들지 않고, 정정 미션의 seed(이미 전기된 선배·지난주의 내 전표)로 만든다
- 종합 실전 장에서 실습자를 승인자로 올린다 (설계 §4의 결재자 역할)
- training-site.md §7의 "1장 뒤로는 사용자가 직접 전기할 수 있는 미션을 섞습니다"를 위 내용으로 바꿨다

## 결과
- 좋은 점
  - 정정이 실무처럼 결재를 거친다. 실습자의 권한(작성자)을 바꾸지 않고 정정 미션을 만들 수 있다
  - 실습 층에 예외 분기가 생기지 않는다. ERP의 일반 기능 하나로 풀린다
- 감수할 점
  - "임시 상태의 역분개"라는 경우가 하나 늘어난다. 전표 목록·입력 화면에 '역분개 요청' 표시와 원전표 링크가 필요하다
  - 핵심 엔진(역분개)이 바뀌므로 회계 노트 02 §5와 [해설 02](../walkthrough/02-journal-engine.md)를 같이 고친다 (CLAUDE.md)
- 면접 포인트: "불변 전표의 정정을 결재 흐름에 어떻게 태웠나", "권한을 올리지 않고 정정을 허용한 방법"

# ADR-0013: 미션은 입력이 아니라 장부의 변화로 채점한다

- 상태: 채택 (2026-11-10)

## 맥락
미션의 정답을 어떻게 판정할지 정해야 한다. 흔한 방법은 "사용자가 입력한 전표의 각 줄이 정답 전표와 같은가"를 비교하는 것인데, 실무 연습에는 맞지 않는다.

- 같은 거래를 맞게 처리하는 방법이 여러 가지다 (줄 순서, 전표 한 장/두 장, 출금 한 줄/차변·대변 두 줄)
- 틀리게 전기한 뒤 **역분개로 정정하고 다시 입력**하는 것은 실무에서 올바른 처리인데, 입력 비교로는 오답이 된다

## 결정
**미션 시작 시점의 잔액과 제출 시점의 잔액의 차이**를 기대한 차이와 비교한다.

```
기대 변화 = 정답 분개의 라인을 (계정, 거래처)별로 합친 것
실제 변화 = 제출 시점 잔액 − 미션 시작 때 저장해 둔 잔액        (계정·거래처별, 전기된 전표 기준)
```

- 기대 변화는 콘텐츠의 정답 분개에서 자동으로 계산한다. 대안 분개는 `accept`로 인정한다
- 시작 시점 잔액은 실습 층이 `mission_attempt`에 저장한다 ([ADR-0012](0012-learning-layer-on-top-of-erp.md))
- 잔액으로 알 수 없는 것만 추가 검사한다: 전표 일자, 부가세 유형·공급가액·세액, 전기 여부, 오류 정정 미션에서 원전표가 남아 있는지
- 결재 요청 흐름에서는 임시 전표를 "전기했다고 가정한" 변화로 먼저 채점하고, 맞으면 팀장(시스템 계정)이 전기한다
- 차이가 있으면 유형(차대 반대, 세액 포함, 계정 오류, 거래처 오류 …)으로 분류해 반려 사유를 만든다. 규칙 기반으로 시작한다

## 결과
- 좋은 점
  - 불변식 5(장부는 전표 라인에서만 파생)가 그대로 채점 근거가 된다
  - 처리 경로가 달라도 결과가 맞으면 통과하고, 정정 절차를 거친 답도 통과한다
  - 채점기를 DB 없이 "잔액 두 벌 + 기대 변화"만으로 단위 테스트할 수 있다
- 감수할 점
  - 미션 도중에 미션과 무관한 전표를 넣으면 변화가 섞여 오답이 된다 → 반려 사유에 "기대하지 않은 변화"를 그대로 보여 준다
  - 서로 상쇄되는 두 가지 실수는 잡지 못한다 (같은 계정·거래처에서 +와 −가 맞아떨어지는 경우). 드물다고 보고 받아들인다
  - 채점에 계정·거래처별 잔액 조회가 필요하다 → 3단계 장부의 일부를 L1에서 먼저 만든다
- 면접 포인트: "정답이 여러 개인 문제를 어떻게 채점했나", "왜 입력 비교가 아닌가"

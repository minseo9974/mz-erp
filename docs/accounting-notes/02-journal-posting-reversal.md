# 회계 노트 02 — 전표, 전기, 역분개, 전표번호

> 전산회계 1급 연결: 실무 "일반전표 입력"(출금·입금·대체), 이론 "회계의 순환과정"(분개 → 전기 → 시산표)

## 한 줄 요약
**분개를 적은 종이가 전표, 전표를 장부(원장)에 옮겨 적는 것이 전기**입니다.
틀린 전표는 지우지 않고 **반대 분개(역분개)** 를 하나 더 만들어 상쇄합니다.

## 1. 회계의 순환과정에서 지금 위치

```
거래 발생 → [분개 = 전표 작성] → [전기 = 원장에 반영] → 시산표 → 결산 → 재무제표
              ▲ 2단계 여기                ▲ 2단계 여기       ▲ 3단계     ▲ 5단계
```

## 2. 전표의 종류 (전산회계 프로그램의 "구분")

| 구분 | 의미 | 예 (시나리오) | 시스템에서 |
| --- | --- | --- | --- |
| 출금전표 | 현금이 나가는 거래 | #35 출장비 450,000 현금 지급 | (차) 812 여비교통비 / (대) **101 현금** |
| 입금전표 | 현금이 들어오는 거래 | (시나리오엔 없음) | (차) **101 현금** / (대) … |
| 대체전표 | 현금이 아예 없거나 일부만 있는 거래 | #6 받을어음 만기 → 보통예금 | (차) 103 보통예금 / (대) 110 받을어음 |

전산회계 프로그램에서 "1.출금"을 고르면 대변 현금이 자동으로 채워집니다. 우리 시스템은 **API가 항상 완성된 차·대 라인만 받고**, 출금·입금 편의 기능은 화면이 처리합니다 (screens.md).

## 3. 전표 한 장이 지켜야 할 규칙 (= 엔진이 검사하는 것)

| 규칙 | 이유 | 어기면 |
| --- | --- | --- |
| 차변 합계 = 대변 합계 | 복식부기의 기본 (노트 01) | `JOURNAL_UNBALANCED` |
| 라인 2줄 이상 | 계정 하나로는 거래를 표현할 수 없음 | `JOURNAL_TOO_FEW_LINES` |
| 한 라인은 차변·대변 중 **한쪽만** | 같은 줄에 양쪽 금액이 있으면 의미가 없음 | `LINE_AMOUNT_INVALID` |
| 금액은 양의 정수(원) | ADR-0002 | `LINE_AMOUNT_INVALID` |
| 거래처 필수 계정이면 거래처 입력 | 외상매출금은 "누구한테 받을 돈인지"가 핵심 | `PARTNER_REQUIRED` |
| 사용 중지·시스템 계정 사용 금지 | 400 손익은 결산 전용 | `ACCOUNT_NOT_POSTABLE` |
| 전표 날짜가 열린 회계기간 안 | 마감된 달의 장부는 바뀌면 안 됨 | `PERIOD_CLOSED` / `FISCAL_PERIOD_NOT_FOUND` |

## 4. 전기(Posting)

- 수기 장부 시대에는 전표(분개장)를 보고 계정별 원장에 한 줄씩 **옮겨 적는** 작업이 전기였습니다.
- 시스템에서는 원장이 전표 라인을 집계해서 만들어지므로(불변식 5), 전기는 **"이 전표를 장부에 반영해도 된다"는 확정 표시**입니다.
- 우리 시스템: `DRAFT(임시)` → **전기** → `POSTED`. 장부·시산표에는 **POSTED 전표만** 들어갑니다 (3단계).
- 전기된 전표는 **수정·삭제 불가** (불변식 2, ADR-0003). 임시 전표는 자유롭게 고치고 지울 수 있습니다.

## 5. 역분개 (Reversing entry)

전기된 전표가 틀렸을 때, 지우는 대신 **차변과 대변을 바꾼 전표를 하나 더** 만듭니다.

**예**: 출장비 450,000을 실수로 812 여비교통비가 아니라 814 통신비로 전기했다면

| 전표 | 차변 | 대변 |
| --- | --- | --- |
| ① 원래 (잘못된) 전표 | 814 통신비 450,000 | 101 현금 450,000 |
| ② **역분개** (①을 뒤집음) | 101 현금 450,000 | 814 통신비 450,000 |
| ③ 올바른 전표 새로 입력 | 812 여비교통비 450,000 | 101 현금 450,000 |

① + ② = 0이 되어 통신비·현금 잔액은 원래대로 돌아가고, ③만 남습니다. 세 전표가 모두 기록으로 남으므로 **"언제 무엇을 왜 고쳤는지"** 가 추적됩니다.

- 역분개 전표는 원전표를 가리킵니다 (`reversal_of_id`). 한 전표는 **한 번만** 역분개할 수 있습니다 (`ENTRY_ALREADY_REVERSED`)
- 역분개 일자: 원전표가 속한 달이 아직 열려 있으면 원전표 날짜, 마감됐으면 정정하는 날짜 (사용자가 지정)
- 역분개 전표는 만들자마자 전기됩니다 (원전표가 이미 확정이므로 상쇄도 바로 확정)

## 6. 전표번호

- 전산회계 프로그램처럼 **회사·일자별 연번** (`2026-03-10` 의 1번, 2번 …). 날짜가 바뀌면 1번부터
- 여러 사람이 동시에 입력해도 **같은 번호가 두 번 나오면 안 됩니다** → DB 한 줄(entry_sequence)을 잠그고 +1 (ADR-0011)
- 임시 전표를 지우면 그 번호는 비게 됩니다. 전기된 전표는 지울 수 없으므로, **장부에 남는 번호는 빠짐없이 이어집니다**

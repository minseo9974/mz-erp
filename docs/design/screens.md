# 화면 설계 (초안)

메뉴 구성은 전산회계 프로그램(KcLep)과 비슷하게 잡았습니다. 시험 공부한 화면과 1:1로 대응되면
"이 메뉴의 숫자가 어떤 쿼리로 나오는지" 설명하기 쉽고, 기능 누락도 바로 보입니다.

## 공통 레이아웃

```
┌──────────────────────────────────────────────────────────────────────────┐
│ MZ-ERP   (주)엠제트전자 ▼   제6기 2026 ▼                       데모 ▼  │
├──────────────┬───────────────────────────────────────────────────────────┤
│ 기초정보     │  [화면 제목]                              [조회] [저장]  │
│ 전표입력     │  ┌─────────────────────────────────────────────────────┐ │
│ 장부조회     │  │ 조회 조건                                           │ │
│ 부가가치세   │  ├─────────────────────────────────────────────────────┤ │
│ 결산/재무제표│  │ 그리드 (AG Grid)                                    │ │
│ 고정자산     │  │                                                     │ │
│ 관리         │  └─────────────────────────────────────────────────────┘ │
└──────────────┴───────────────────────────────────────────────────────────┘
```

- 상단에서 회사·회계연도를 고르면 모든 화면이 그 기준으로 동작
- 키보드 중심: Enter로 다음 칸, **F2 = 코드 도움**(계정·거래처 검색 팝업), F3 = 저장, Esc = 닫기
- 금액은 오른쪽 정렬, 천 단위 쉼표, 음수는 괄호

## 일반전표 입력

```
일반전표 입력                                   2026 년 [03] 월 [  ] 일   [조회]
┌────┬────┬────┬──────────┬────────────────┬────────────────┬─────────────┬─────────────┐
│ 일 │번호│구분│ 계정과목 │ 거래처         │ 적요           │      차변   │      대변   │
├────┼────┼────┼──────────┼────────────────┼────────────────┼─────────────┼─────────────┤
│ 10 │0001│차변│103 보통예금│               │받을어음 만기   │  5,000,000  │             │
│ 10 │0001│대변│110 받을어음│00101 (주)한빛전자│받을어음 만기 │             │  5,000,000  │
│ 20 │0001│차변│251 외상매입금│00201 (주)대성소재│외상매입금 지급│ 7,000,000 │             │
│ 20 │0001│대변│103 보통예금│               │외상매입금 지급 │             │  7,000,000  │
│ 31 │0001│차변│252 지급어음│00201 (주)대성소재│지급어음 결제 │ 3,000,000  │             │
│ 31 │0001│대변│103 보통예금│               │지급어음 결제   │             │  3,000,000  │
└────┴────┴────┴──────────┴────────────────┴────────────────┴─────────────┴─────────────┘
 선택 전표 0001 (03-10)   차변 합계 5,000,000   대변 합계 5,000,000   차액 0   상태: 임시
                                                 [전기(F8)] [역분개] [삭제]
```

- **구분**: 1 출금 · 2 입금 · 3 차변 · 4 대변. 출금·입금은 상대편 현금(101) 라인을 자동으로 만들고 화면에 "(현금)"으로 표시 — 예: 시나리오 #35 출장비는 "출금 · 812 여비교통비 450,000" 한 줄 입력으로 끝
- 같은 일자·번호의 행이 한 전표. 차액이 0이 아니면 저장 버튼 비활성화 + 차액을 빨간색으로
- 거래처 필수 계정을 고르면 거래처 칸이 필수로 바뀜
- 전기된 전표 행은 회색, 편집 불가. 역분개된 전표는 취소선 + 역분개 전표 번호 링크
- 마감된 월을 고르면 상단에 "마감된 기간입니다" 배너, 입력 불가

### 구현 메모 (2단계)

코드: `frontend/src/pages/journal/` — 변환·검증은 `entryForm.ts`(순수 함수, 테스트 `entryForm.test.ts`), 화면은 `EntryEditor.tsx`.

| 항목 | 구현 |
| --- | --- |
| 화면 구성 | 위: 그 달의 전표 라인 목록(AG Grid, 행 클릭 = 열기). 아래: 전표 한 장 편집기(일반 표 + input — 키보드 제어와 테스트가 쉬움) |
| 구분 | 숫자 한 자리 입력 칸 (1 출금 · 2 입금 · 3 차변 · 4 대변). `select`는 숫자 타이핑이 브라우저마다 달라 바꿈 |
| 출금·입금 | 화면에서만 존재. 저장할 때 현금 라인을 붙여 차변·대변 2줄로 보낸다. 다시 열면 "2줄 + 한쪽이 현금 + 금액 같음"인 전표만 1줄로 접어서 보여 준다 |
| 현금 계정 101 | 입력 편의 기본값이라 상수 하나(`CASH_ACCOUNT_CODE`)로 둠. 불변식 6(계정코드 하드코딩 금지)은 장부·결산 판단 로직 대상이라 예외. 회사 계정표에 101이 없거나 사용 중지면 출금·입금을 막는다 |
| 키보드 | Enter = 다음 칸, F2 = 코드 도움, 코드 칸에 이름 일부를 치고 Enter = 코드 도움, F3 = 저장, F8 = 전기 |
| 차액 자동 줄 | 마지막 칸에서 Enter: 차액이 있으면 반대편 줄을 차액·같은 적요로 추가, 0이면 저장 버튼으로 이동 |
| 한글 입력 | 글자 조합 중 Enter(`isComposing`)는 무시 — 조합을 끝내는 Enter로 칸이 넘어가면 마지막 글자가 빠진다 |
| 검증 | 화면은 계정·거래처 필수·금액·차액을 미리 알려 주기만 한다. 같은 규칙을 서버(`JournalService`, `JournalEntry`)와 DB 트리거가 다시 검사 |
| 권한 | 전기·역분개 버튼은 승인자·관리자에게만. 작성자에게는 안내 문구 |
| 적요 | 줄마다 입력. 전표 머리 적요(`description`)는 첫 번째 줄 적요로 채운다 |

- 54 불공은 사유를 고르는 칸이 나타나고, 아래 분개에 부가세대급금이 생기지 않음
- 51 과세 매입에서 계정이 유형자산(212 비품 등)이면 "고정자산 매입" 표시 → 신고서 고정자산매입 란으로 집계

## 프론트엔드 구현 메모

| 항목 | 결정 |
| --- | --- |
| 라우팅 | React Router, 메뉴 = URL (`/companies/1/journal-entries?month=2026-03`) — 새로고침·북마크해도 같은 화면 |
| 서버 상태 | TanStack Query. 전표 저장·전기 후 장부·시산표 쿼리 무효화 |
| 그리드 | AG Grid Community. 셀 편집 + 키보드 이동, 금액 셀 포맷터·파서 공통 컴포넌트 |
| 코드 도움 | F2 팝업 공통 컴포넌트 (계정·거래처 공용), 코드 직접 입력 시 이름 자동 표시 |
| 타입 | OpenAPI 스펙에서 TypeScript 타입 생성 (openapi-typescript) |
| 금액 | 프론트도 정수만. 입력 파서는 쉼표 제거 후 `Number.isSafeInteger` 확인 |
